# 3. MARCO TEÓRICO

---

## 3.1 Fundamentos teóricos

El desarrollo del **Sistema Integral de Análisis y Reporte Académico (SIARA)** se sustenta en estándares modernos de ingeniería de software, arquitecturas web empresariales de Microsoft y los lineamientos normativos vigentes del Tecnológico Nacional de México.

---

### 3.1.1 Patrón Arquitectónico Modelo-Vista-Controlador (MVC)

El patrón **Modelo-Vista-Controlador (MVC)** es un estilo de arquitectura de software que separa los datos de una aplicación, la interfaz de usuario y la lógica de control en tres componentes interconectados con responsabilidades claramente definidas (Gamma et al., 1994; Freeman, 2023):

1. **Modelo (*Model*):** Representa el estado de la aplicación, las entidades del dominio de negocio y las reglas de integridad de datos. En SIARA, el Modelo está conformado por las clases de entidad persistidas en SQL Server (`Subject`, `DocumentTask`, `Document`, `AcademicTracking`, `DocenteAsignatura`, etc.) y los modelos de vista (`AnalyticsDashboardViewModel`, `SubjectHistoryViewModel`) que transportan información procesada hacia la interfaz.
2. **Vista (*View*):** Es la capa de presentación encargada de transformar los datos del modelo en una interfaz gráfica interactiva para el usuario final. En el proyecto se implementa mediante el motor de plantillas **Razor (`.cshtml`)**, combinando marcado HTML5, hojas de estilo **Bootstrap 5** y expresiones de C# del lado del servidor.
3. **Controlador (*Controller*):** Actúa como el coordinador central que recibe las peticiones HTTP (`GET`, `POST`) enviadas desde el navegador, verifica los permisos del usuario en sesión, ejecuta las reglas de negocio mediante consultas a la base de datos y selecciona la Vista o respuesta (como un archivo PDF o Excel) que debe devolverse al cliente.

Esta separación de responsabilidades (*Separation of Concerns*) facilita el mantenimiento evolutivo del sistema, previene la duplicación de código y permite modificar las vistas sin alterar las reglas de cálculo estadístico del backend.

### 3.1.2 Framework ASP.NET Core 9 y Lenguaje C#

**ASP.NET Core 9** es el framework de código abierto, multiplataforma y de alto rendimiento desarrollado por Microsoft para la construcción de aplicaciones web modernas y servicios en la nube (Microsoft, 2024). Entre las características técnicas de **.NET 9** y **C# 13** aplicadas directamente en SIARA destacan:

- **Canalización de Middleware (*Request Pipeline*) optimizada:** En `Program.cs` se configura un flujo secuencial y ligero que gestiona el redireccionamiento HTTPS, archivos estáticos (`wwwroot`), enrutamiento de controladores, autenticación por cookies y autorización basada en roles.
- **Inyección de Dependencias (DI) nativa:** El contenedor de inversión de control (IoC) integrado en ASP.NET Core administra el ciclo de vida (*Scoped*) del contexto de datos `ApplicationDbContext` y de los servicios de identidad (`UserManager<ApplicationUser>`, `RoleManager<IdentityRole>`), inyectándolos de forma segura en los constructores de cada controlador.
- **Programación Asíncrona (`async` / `await`):** Todas las operaciones de lectura y escritura hacia SQL Server y el sistema de archivos (carga de PDFs en `DocumentsController`) se ejecutan de forma asíncrona mediante `Task<IActionResult>`, evitando el bloqueo de hilos en el servidor web Kestrel/IIS cuando múltiples docentes suben evidencias simultáneamente en días de cierre de buzón.

---

### 3.1.3 Mapeo Objeto-Relacional con Entity Framework Core 9 (Code-First)

**Entity Framework Core (EF Core) 9** es un mapeador objeto-relacional (O/RM) moderno que permite a los desarrolladores de .NET trabajar con bases de datos relacionales utilizando objetos de dominio fuertemente tipados en C#, reduciendo la necesidad de escribir sentencias SQL manuales propensas a errores o inyecciones SQL (Smith, 2024).

En SIARA se adoptó la metodología **Code-First con Migraciones**:
- **Definición mediante Clases y Data Annotations:** Las tablas, llaves primarias, longitudes máximas y rangos de validación (como `[Range(1, 12)]` en el semestre de la asignatura o `decimal(5,2)` para porcentajes) se declaran directamente en las clases de C#.
- **Configuración con Fluent API (`OnModelCreating`):** En `ApplicationDbContext.cs` se definen con precisión las relaciones uno a muchos y muchos a muchos (como la entidad asociativa `DocenteAsignatura` enriquecida con `Group` y `Turno`), así como las políticas de borrado (`DeleteBehavior.Restrict` y `DeleteBehavior.Cascade`) para evitar ciclos de cascada en SQL Server y proteger el historial académico.
- **Consultas LINQ to Entities y Carga Explícita (*Eager Loading*):** A través de operadores LINQ combinados con `.Include()` y `.ThenInclude()`, el sistema recupera grafos relacionales completos (por ejemplo, una tarea con sus documentos, seguimientos, materias y docentes adscritos) en consultas SQL parametrizadas de alta eficiencia.

### 3.1.4 Seguridad, Autenticación Basada en Cookies y Control de Acceso Jerárquico (ASP.NET Core Identity)

La seguridad de la información académica es un pilar crítico del proyecto. Para ello se implementó **ASP.NET Core Identity**, un sistema de membresía empresarial que gestiona usuarios, hash criptográfico de contraseñas (PBKDF2), tokens antifalsificación (`[ValidateAntiForgeryToken]`) y emisión de cookies de autenticación cifradas.

Sobre esta base, SIARA implementa un modelo híbrido de **Control de Acceso Basado en Roles (RBAC)** y **Aislamiento Multi-Tenant por Departamento**:
1. **Autorización Declarativa:** Mediante el atributo `[Authorize(Roles = "...")]` a nivel de clase y de método de acción, se restringe el acceso a rutas específicas según los cuatro perfiles del sistema (`Administrador`, `JefeGeneral`, `JefeCarrera` y `Docente`).
2. **Filtro de Ámbito Departamental (*Tenant Isolation*):** Cada usuario `ApplicationUser` y cada asignatura `Subject` poseen una llave foránea `DepartamentoId`. Los controladores verifican en tiempo de ejecución que un Jefe de Carrera solo pueda consultar, editar o auditar las asignaturas, buzones y seguimientos pertenecientes a su propio `DepartamentoId`, incluso cuando la materia sea impartida por un profesor invitado en modalidad de préstamo interdepartamental.
3. **Candado Jerárquico:** Se programaron validaciones de negocio que impiden la escalada horizontal o vertical de privilegios, garantizando que ningún revisor auxiliar pueda revocar al Jefe de Carrera titular ni alterar la cuenta del Administrador general.

### 3.1.5 Motores de Generación de Documentos: QuestPDF y ClosedXML

Para satisfacer el requerimiento de exportación formal de sábanas analíticas sin depender de instalaciones de Microsoft Office en el servidor, se integraron dos bibliotecas especializadas en memoria (`MemoryStream`):

- **QuestPDF (`v2026.2.1`):** Es un motor moderno de composición de documentos PDF para .NET basado en una API fluida (*Fluent C# API*). A diferencia de los convertidores HTML-a-PDF tradicionales, QuestPDF diseña el documento mediante contenedores tipados (encabezados institucionales, tablas dinámicas con paginación automática, indicadores de color y pies de página numerados), generando archivos PDF vectoriales ligeros y listos para firma o impresión oficial en milisegundos.
- **ClosedXML (`v0.105.0`):** Es una biblioteca construida sobre el estándar *OpenXML SDK* que permite crear, dar formato y exportar libros de cálculo nativos de Microsoft Excel (`.xlsx`). En `ReportsController`, ClosedXML se utiliza para construir la **Sábana Analítica de Rendimiento**, aplicando estilos de celda, encabezados con el azul institucional del TecNM (`#112d60`), ajuste automático de columnas (`AdjustToContents()`) y resaltado condicional para unidades con alto índice de reprobación.

### 3.1.6 Lineamientos y Normativas Académicas del TecNM para la Instrumentación Didáctica y Seguimiento Docente

El diseño funcional de SIARA traduce fielmente los procedimientos establecidos en el **Manual de Lineamientos Académico-Administrativos del Tecnológico Nacional de México** (TecNM, 2015) referentes a la Gestión del Curso:

- **Entrega Inicial (Planeación):** Al inicio del semestre, el profesor debe entregar la *Instrumentación Didáctica para la Formación y Desarrollo de Competencias Profesionales*, la *Evaluación Diagnóstica* y la planeación de *Prácticas* o *Proyectos*.
- **Seguimientos Parciales (1.º, 2.º y 3.º / Final):** Durante el transcurso del periodo escolar, la Jefatura de Departamento Académico realiza cortes periódicos para verificar el avance programático del temario y recabar las estadísticas de acreditación por unidad de competencia.
- **Índice de Reprobación y Acción Correctiva:** Cuando en una evaluación de unidad se detecta un porcentaje elevado de estudiantes que no alcanzan la competencia (establecido como umbral de alerta institucional en **$\ge 40\%$ de reprobación**), el docente debe documentar las causas y proponer una estrategia de nivelación o **Acción Correctiva**, la cual debe ser validada y supervisada por el Jefe del Departamento Académico.
- **Reporte Final del Semestre:** Al concluir el ciclo, se consolida el acta de calificaciones definitivas y el concentrado global del departamento para su envío a la Subdirección Académica.
